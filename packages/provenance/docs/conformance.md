# Conformance

Two suites ship with the package. Both use the same vector shape:

```json
{ "format_version": 1, "kind": "<kind>", "id": "<id>", "description": "…", "input": { … }, "expected": { … } }
```

and the same manifest shape (`vectors: [{path, kind, id, sha256}]`,
`suite_hash = sha256(canonical(vectors))`). Hashes, hex signatures and
canonical strings compare exactly; structured results compare JSON-equal
after canonicalization.

| Suite | Origin | Kinds | Where |
|---|---|---|---|
| **finance v1** | generated by the TypeScript reference `@kernel.chat/kbot-finance@0.3.0`, vendored unchanged | canonicalize, source_document, claim_shape, arithmetic, reconcile, reconcile_envelope, ledger_rules, approval_summary, approval_token, approval_verify, ledger_entry_id, audit_chain, ledger_post | `src/provsubstrate/conformance/vectors_finance_v1/` |
| **academic v1** | generated by this package's reference implementation | `lean_*`, `claim_*`, `repro_*`, `bench_*`, `review_*` (see each wedge doc) | `src/provsubstrate/conformance/vectors_academic_v1/` |

## Running

```bash
provsub conformance finance-v1            # this implementation against the vendored TS suite
provsub conformance academic-v1           # this implementation against its own suite
provsub conformance --check               # regenerate academic v1 in memory and diff against disk
provsub conformance finance-v1 --json     # machine-readable report
```

From Python:

```python
from provsubstrate.conformance import run_conformance, FINANCE_V1_DIR, ACADEMIC_V1_DIR
from provsubstrate.finance.conformance import ALL_FINANCE_V1_HANDLERS
report = run_conformance(FINANCE_V1_DIR, ALL_FINANCE_V1_HANDLERS)
print(report.summary())    # 143/143 passed; suite be4cdbe3e0a53bbd… manifest ok
```

## Porting to another language

Implement handlers for the kinds you claim. Point the runner (or your own
loader — the format is trivial) at the vectors directory. A port that only
implements some kinds must say which, and must quote the `suite_hash`.

Two negative controls are worth reproducing in your own test suite: an
implementation that auto-picks the first candidate when a reconciliation is
ambiguous fails exactly the ambiguity vectors; an implementation that forgets
to sort keys fails every hash-bearing kind. If your port fails a vector, the
vector's `description` says what it pins.

## Versioning

`format_version` is the vector schema. `manifest.reference_versions` pins
the reference package and engines the vectors were generated against. A
change to any pinned behaviour is a new suite hash and, if semantic, a new
directory (`v2`). Old suites are never edited in place.

## Why byte-for-byte

A hash is only a replay key if two honest implementations compute the same
one. The finance v1 canonicalize vectors pin JavaScript number formatting
(`1e+21`, `1e-7`, `123456789012345680000`), `JSON.stringify` escaping, and
UTF-16 key ordering. The Python implementation is fuzzed against V8 on a
thousand random doubles in `tests/`.
